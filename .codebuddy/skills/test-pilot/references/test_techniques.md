# Test Techniques - Quick Reference

## 1. Equivalence partitioning (equiv-class / 等价类划分)
Divide inputs into groups expected to behave identically; test one representative
per group.
- Valid class(es): inputs that should succeed.
- Invalid classes: empty, wrong type, out-of-range, malformed.

Example: age input 0-120 valid; <0, >120, non-numeric, empty are invalid classes.

## 2. Boundary value analysis (边界值分析)
Test values at the edges of each equivalence class.
- For range [min, max]: test min-1, min, min+1, max-1, max, max+1.
- Catches off-by-one and inclusive/exclusive mistakes.

## 3. Decision tables (决策表)
List conditions and the rules/actions for each combination. Great for business
rules with several booleans.
- Columns = combinations; rows = conditions + expected action.
- Test one case per non-trivial column.

## 4. State-transition (状态迁移)
For stateful objects (sessions, orders, connections): enumerate states and events.
- Test every valid transition.
- Test invalid transitions (event in wrong state -> rejected).

## 5. Property-based testing (属性测试)
Assert invariants that hold for ALL inputs generated by the framework.
- Examples: `sort(x)` is idempotent and length-preserving;
  `encode(decode(x)) == x`; a parser never throws on valid grammar.
- Tools: Python hypothesis, JS fast-check, Java jqwik, Haskell QuickCheck,
  Rust proptest.

## Worked example: login validator

Function `validate_login(username, password)` returns `(ok: bool, reason: str)`.

**Equivalence classes**
- username: valid (alphanumeric 3-20), too short, too long, empty, with spaces,
  with symbols.
- password: meets policy (>=8 with digit+letter), too short, no digit, empty.

**Boundary values** (username length 3-20): lengths 2, 3, 4, 19, 20, 21.

**Decision table** (simplified): username valid? x password valid? -> (ok, reason).

**State transition** (session): logged-out ->(correct creds)-> logged-in;
logged-in ->(logout)-> logged-out; logged-out ->(wrong creds)-> stays logged-out
and increments fail count; after N fails -> locked.

**Property**: for any valid (username, password) that was registered,
`validate_login` returns ok after correct registration (if a registration path
exists).

## Framework-detection checklist
- Python: check requirements.txt / pyproject for pytest or unittest -> use pytest.
- JS/TS: read package.json "scripts.test" and devDeps (jest/vitest/mocha).
- Go / Rust: built-in; just run `go test` / `cargo test`.
- Java / Kotlin: pom.xml or build.gradle -> mvn / gradle test with JUnit.
- C#: `dotnet test` with xUnit / NUnit.
- Ruby: Gemfile -> rspec / minitest.
Always reuse what the project already has; do not introduce a new framework
unnecessarily.
