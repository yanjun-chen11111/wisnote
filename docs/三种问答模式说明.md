# 三种问答模式说明

> 三种模式共用同一个 Qwen3-1.7B，靠"是否检索 + 不同 Prompt"区分，
> 符合计划书"单模型多任务、只加载一次"的设计。

## 📚 笔记问答（严格模式 · 可溯源）

**流程**：问题 → 直接检索自己的笔记 → 只把检索到的片段交给模型 → 生成回答（标注 `[1][2]`）

| 特性 | 说明 |
|---|---|
| 检索 | ✅ 只用当前问题检索，**每轮独立** |
| 历史对话 | ❌ 完全不参考 |
| 溯源 | ✅ 显示文件/页码/段落，可看 PDF 原文高亮 |
| 笔记里没有时 | **明确拒答**："笔记中没有相关内容，我无法据此回答" |
| 保存记录 | ✅ 自动存入聊天记录 |

**适合**：需要确保答案可信、可核对来源的场景（复习、写论文引用、验证 AI 是否胡说）。
**代价**：追问（"那怎么避免？"）可能检索不到而拒答；笔记里没有的知识答不了。
**定位**：项目核心卖点模式，答辩主推。

## 🔀 智能模式（自动切换 · 兼顾两者）

**流程**：问题 → 检索笔记 → 判断命中程度 → 命中则基于资料回答（带溯源）；
未命中则转为通用回答（无溯源）

| 特性 | 说明 |
|---|---|
| 检索 | ✅ 每次都检索，结果不好则自动放弃 |
| 历史对话 | ✅ 默认带（可关） |
| 溯源 | ⚠️ 命中才有；未命中时界面提示"已转为通用回答（无溯源）" |
| 笔记里没有时 | 自动用模型自身知识回答（不再拒答） |
| 保存记录 | ✅ |

**适合**：日常最省心——有资料用资料，没有也能聊。
**代价**：答案来源可能混合，严谨性不如笔记问答；溯源时有时无。
**演示建议**：讲完笔记问答后，用它展示"AI 知道什么时候该说不知道，什么时候可以通用回答"。

## 💬 自由对话（通用助手 · 不依赖资料）

**流程**：问题 → **不检索** → 直接用模型自身知识回答（带多轮上下文）

| 特性 | 说明 |
|---|---|
| 检索 | ❌ 不查笔记库 |
| 历史对话 | ✅ 默认带（8 条 ≈ 4 轮），长对话自动压缩为摘要 |
| 溯源 | ❌ 无（本来就没用资料） |
| 笔记里没有时 | 照常回答 |
| 保存记录 | ✅ |

**适合**：通用学习助手、概念科普、不要求引经据典的问题。
**代价**：1.7B 小模型自身知识有限，复杂推理/数学题可能出错；无溯源，无法核对。
**诚实提醒**：该模式回答不可作为论文引用依据，演示时别当作亮点——亮点是笔记问答。

## 怎么选

| 需求 | 模式 |
|---|---|
| 要答案可信、能核对原文 | 📚 笔记问答 |
| 不确定笔记里有没有，想尽量答出来 | 🔀 智能模式 |
| 问笔记之外的问题、随便聊聊 | 💬 自由对话 |

## 三个模式的共同点

1. **都自动保存聊天记录**（写入 `chat_messages`，含引用来源 JSON），可在「聊天记录」页回看、继续、搜索；
2. **都自动给会话命名**（第一轮结束后，≤12 字）；
3. **都支持流式输出**（边生成边显示）；
4. **都用同一个模型**，不额外占用内存；
5. 都受"带入对话上下文"开关控制（笔记问答默认关闭 = 纯单轮独立检索）。

## 设计要点：检索与生成分离

- 检索阶段：决定"找什么"；
- 生成阶段：只依据本轮检索片段作答。
- 这样保证**溯源无歧义**——答案里每一句话都能在本轮列出的来源中找到，
  不会出现"答案来自上一轮资料、溯源却只列本轮片段"的矛盾。
