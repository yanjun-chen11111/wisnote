# 检索排名的影响因素

> 2026-10 更新：检索已从纯语义升级为**混合检索**（BM25 关键词 + 语义向量，RRF 融合），
> 本文对应混合架构重写。升级动机与评测数据见文末。

## 现在的排名由谁决定？

```
提问 query ──┬── 语义路：bge-small 向量化 → ChromaDB 余弦相似度 → 排名 Top-5
             │
             └── BM25 路：jieba 分词 → SQLite 全量索引 → Okapi BM25 → 排名 Top-5
                        ↓ 两路在 wisnote/hybrid.py 用 RRF 融合
             最终 Top-5（rrf_score 排序）→ search.py 补文档标题等溯源信息
```

**排序不再由单一环节决定**，而是两路排名融合的结果。这是 RAG 领域的主流做法
（Elasticsearch、LangChain、LlamaIndex 都内置了同样的混合方案）。

## 为什么需要混合？两路各自的盲区

| 路线 | 强项 | 盲区 |
|------|------|------|
| 语义（bge 向量） | 同义改写（"页面淘汰" ≈ "页面置换"） | 专有名词、ID、缩写等**字面精确匹配**（向量分不开稀有词） |
| BM25 关键词 | 字面命中精准、可解释 | 换个说法就漏（零词重叠的改写题全军覆没） |

实测（eval/goldset.csv，18 题）："怎么保证发出去的数据一个都不丢"——语义路完全没命中，
BM25 抓到 Top2，混合后回到 Top4。反过来字面题主要靠 BM25 托底。

## RRF 融合怎么工作（wisnote/hybrid.py）

每个 chunk 的融合分 = `Σ 1/(60 + rank)`（各路排名取倒数相加）：

- 两路都命中的 chunk 分数最高（1/61 + 1/61 > 1/61）——"双证据"优先；
- **只用排名、不用原始分数**：BM25 分数无上界、语义分数在 0~1，量纲不可比，
  看排名就绕开了归一化难题（k=60 是业界默认，Elasticsearch 同款）；
- 两路数据源 chunk_id 格式不同（SQLite `chunk{id}` vs Chroma `doc{doc}_chunk{i}`），
  合并去重用 **(document_id, chunk_index)** 这个可靠对齐键。

## 防幻觉闸门为什么不受影响

闸门（`min_similarity` 拒答阈值）**只看最高语义相似度**（`max_semantic_similarity`），
BM25 分数和 RRF 排名不参与。职责分离：

- **RRF 融合排名** → 决定"给 LLM 哪些笔记片段"；
- **语义相似度阈值** → 决定"要不要回答"（防止笔记里没有相关内容时硬编）。

仅 BM25 命中、语义分只有 0.0 的 chunk 不会抬升闸门。

## 真正影响检索结果的环节（按影响从大到小）

| 环节 | 所在位置 | 影响什么 |
|------|----------|----------|
| Embedding 模型 | `config.py` 的 `EMBEDDING_MODEL` | 语义路理解能力的上限 |
| **BM25 参数** | `bm25.py`（k1=1.5, b=0.75）与 jieba 分词 | 字面路质量；分词错误直接漏检 |
| **RRF 常数** | `config.py` 的 `RRF_K`（默认60） | 两路平衡；一般不用动 |
| 混合开关 | `config.py` 的 `HYBRID_RETRIEVAL` | False 可回退纯语义做对比实验 |
| 切块大小/重叠 | `config.py` 的 `CHUNK_SIZE / CHUNK_OVERLAP` | 两路共同的数据底座 |
| 解析质量 | `wisnote/parsers/` | 进库原文干不干净 |
| 返回条数 | `config.py` 的 `SEARCH_TOP_K`（默认5） | 只影响看几条，不影响谁排前面 |

## 三个角色变成四个

| 角色 | 是谁 | 干什么 |
|------|------|--------|
| 翻译官 | bge-small-zh-v1.5 | 中文 → 512 维向量，管"意思像不像" |
| 图书管理员 | ChromaDB | 存块向量，算余弦相似度 |
| 关键词专家 | BM25（SQLite + jieba） | 管"字面有没有"，按用户缓存索引（语料指纹失效） |
| 调度员 | `wisnote/search.py` + `hybrid.py` | 调度两路，RRF 融合，附溯源信息 |

## 升级评测数据（2026-10-13，18 题 goldset，负例 2 题全过）

| 指标 | 语义 | BM25 | **混合 RRF** |
|------|------|------|----------|
| Recall@3 | 88.9% | 100% | **94.4%** |
| Recall@5 | 94.4% | 100% | **100%** |
| MRR | 0.900 | 0.972 | **0.921** |

解读（如实记录，不粉饰）：
- 混合相对**旧产品基线（纯语义）全面提升**：R@5 +5.6pp，零回归，闸门不破——这是上线依据；
- 纯 BM25 在本 goldset 上比混合高（R@1 94.4% vs 88.9%），原因：该 goldset 字面题占 13/18、
  语料只有 2 个文件，天然偏向 BM25。**BM25 的盲区（零词重叠的改写）在真实用户提问里更常见**，
  语料增长后差距会反转——这也是业界不单独用 BM25 而做混合的原因；
- 若未来想再提升，可试调小 RRF_K 或给两路不同权重，但 goldset 只有 18 题，调参容易过拟合，
  暂不动（先攒题量）。
