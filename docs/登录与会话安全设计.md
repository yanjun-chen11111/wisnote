# 登录与会话安全设计（WisNote）

## 当前方案：会话令牌存于 sessionStorage（标签页级）

登录令牌由服务端签发，客户端存于浏览器 **sessionStorage**（按标签页隔离）。刷新保留、关闭标签页 / 浏览器即失效，且令牌绝不出现在地址栏。

| 存储 | 作用 |
|---|---|
| **sessionStorage** | 令牌本体（标签页级）；服务端从组件回传读取，刷新稳定、关闭标签页或浏览器即清空 |

> 说明：早期曾考虑「会话 Cookie + 标签页 ID 绑定」（用 `visibilitychange` 检测关标签页）的方案，但它依赖脆弱的关页检测、易出边界 bug；最终采用的 **sessionStorage** 直接利用平台原生的「标签页级」语义，干净地得到相同行为，无需任何 hack。

## 行为

| 刷新页面 | 关标签页再开 | 关浏览器再开 | 地址栏 | 闪屏 |
|:---:|:---:|:---:|:---:|:---:|
| ✅ 保持 | ❌ 重登 | ❌ 重登 | ✅ 干净 | 无（首帧未回传令牌时会自动重跑一次以可靠恢复） |

## 服务端会话

- **签发**：`auth.login` 用 `secrets.token_hex(32)` 生成随机令牌，写入 `sessions` 表（关联 user_id）。
- **校验**：`get_user_by_token` 校验令牌存在且未超过服务端有效期。
- **有效期**：12 小时（`config.py` 的 `SESSION_TTL_HOURS = 12`），过期由 `purge_expired_sessions` 清理。
- **吊销**：`revoke_all_sessions` 可一键下线全部设备（令牌疑似泄露时止损）；`logout` 销毁单个会话。

## 多层防护

- **地址栏无令牌**：令牌只存于 sessionStorage，绝不出现在 URL，防截图与历史泄露。
- **服务端有效期 + 吊销**：12h 过期、可一键全量吊销。
- **退出即销毁**：点「退出登录」同时清除 sessionStorage 与服务端会话；「吊销全部令牌」立即下线所有设备。
- **不写磁盘**：无令牌文件，无本地长期钥匙。

## 已知权衡

- **sessionStorage vs HttpOnly Cookie**：当前用 sessionStorage，令牌在前端 JS 可读（非 HttpOnly），理论上 XSS 暴露面略大于 HttpOnly Cookie；换来的是原生「关标签页即失效」的行为，符合本项目的轻量演示定位。若以后想改为「关标签页仍保持登录」（更常见的 Web 产品行为），可切换为服务端会话 + HttpOnly 会话 Cookie（令牌不暴露给 JS）——这正是工程教练里提到的标准模式。
- **标签页崩溃 / 恢复**：浏览器恢复崩溃标签页时 sessionStorage 可能被保留（因厂商而异），属边缘情况。

## 数据流

```
登录成功 → persist_login(token)
  ├─ 组件写 sessionStorage["wisnote_token"] = token
  └─ 清空地址栏参数

刷新（同标签页）→ 组件回传 sessionStorage 令牌 → try_restore_session 校验通过 → 保持登录

关闭标签页 / 浏览器 → sessionStorage 清空 → 再次打开比对失败 → 回到登录页

退出 / 吊销 → 客户端 sessionStorage 清空 + 服务端 sessions 行删除
```

## 涉及模块

- `ui/app.py`：`persist_login` / `try_restore_session` / `clear_login`（注：无 `enforce_tab_binding`，标签页失效由 sessionStorage 原生保证）
- `ui/wisnote_cookie_component/index.html`：写 / 删 / 回传 sessionStorage 中的令牌（组件名含 cookie 但实为 sessionStorage）
- `wisnote/auth.py`：`login` / `get_user_by_token` / `purge_expired_sessions` / `revoke_all_sessions` / `logout`
- `wisnote/config.py`：`SESSION_TTL_HOURS`
