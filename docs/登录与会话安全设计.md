# 登录与会话安全设计（WisNote）

## 当前方案：会话令牌存于 sessionStorage（标签页级）

登录令牌由服务端签发，客户端存于浏览器 **sessionStorage**（按标签页隔离），经自建 Streamlit 组件（`ui/wisnote_cookie_component/index.html`）读写与回传。令牌绝不出现在地址栏。

| 存储 | 作用 |
|---|---|
| **sessionStorage** | 令牌本体（标签页级）；组件回传后由 `try_restore_session` 校验 |

## 实际行为（实测为准）

| 刷新页面 | 关标签页再开 | 关浏览器再开 | 地址栏 | 闪屏 |
|:---:|:---:|:---:|:---:|:---:|
| ❌ 重登 | ❌ 重登 | ❌ 重登 | ✅ 干净 | 无 |

> 设计意图曾是「刷新保持、关标签页/浏览器重登」，但**实测刷新也会掉登录**（见「已知问题」）。本文档以实测行为为准。

## 已知问题：刷新会掉登录

- **现象**：硬刷新（F5）后回到登录页，需重新登录。
- **根因（推测）**：令牌依赖自建 iframe 组件**异步回传** sessionStorage 值；Streamlit 硬刷新会重置 `st.session_state`，且组件值在脚本首帧尚未回传，导致 `try_restore_session` 第一帧读不到令牌即判定未登录。sessionStorage 在同源同标签页刷新后本应保留，但当前组件回传时序不稳，未能可靠恢复。
- **影响**：三项诉求中「刷新保持」实际未达成，体验接近「关浏览器才失效」的反面（反而更脆弱）。

## 服务端会话

- **签发**：`auth.login` 用 `secrets.token_hex(32)` 生成随机令牌，写入 `sessions` 表（关联 user_id）。
- **校验**：`get_user_by_token` 校验令牌存在且未超过服务端有效期。
- **有效期**：12 小时（`config.py` 的 `SESSION_TTL_HOURS = 12`），过期由 `purge_expired_sessions` 清理。
- **吊销**：`revoke_all_sessions` 可一键下线全部设备（令牌疑似泄露时止损）；`logout` 销毁单个会话。

## 多层防护

- **地址栏无令牌**：令牌只存于 sessionStorage，绝不出现在 URL，防截图与历史泄露（此项实测有效）。
- **服务端有效期 + 吊销**：12h 过期、可一键全量吊销。
- **退出即销毁**：点「退出登录」同时清除 sessionStorage 与服务端会话；「吊销全部令牌」立即下线所有设备。
- **不写磁盘**：无令牌文件，无本地长期钥匙。

## 已知权衡 / 待决策

- **sessionStorage vs HttpOnly Cookie**：当前 sessionStorage 方案在刷新时不可靠（见已知问题）。若改为 **服务端会话 + HttpOnly 会话 Cookie**（令牌不暴露给 JS、随每次请求自动带上），可稳定实现「刷新保持 ✅ + 关浏览器重登 ✅」，但「关标签页」也会保持登录（这是绝大多数网站的标准 Web 行为）。该方案更稳、更符合工程教练一直推荐的标准做法，代价是放弃「关标签页立即重登」这一非标准诉求。
- **要硬保「关标签页重登」**：需回到「Cookie + 标签页 ID 绑定 / visibilitychange 检测」的脆弱方案，边界 bug 多，不推荐。

## 数据流

```
登录成功 → persist_login(token)
  ├─ 组件写 sessionStorage["wisnote_token"] = token
  └─ 清空地址栏参数

刷新（同标签页）→ 组件应回传 sessionStorage 令牌 → try_restore_session 校验
  ⚠ 实测：硬刷新时首帧读不到令牌 → 判定未登录 → 回到登录页（待修复）

关闭标签页 / 浏览器 → sessionStorage 清空 → 再次打开比对失败 → 回到登录页

退出 / 吊销 → 客户端 sessionStorage 清空 + 服务端 sessions 行删除
```

## 涉及模块

- `ui/app.py`：`persist_login` / `try_restore_session` / `clear_login`（注：无 `enforce_tab_binding`，标签页失效由 sessionStorage 原生保证；刷新恢复逻辑目前不可靠）
- `ui/wisnote_cookie_component/index.html`：写 / 删 / 回传 sessionStorage 中的令牌（组件名含 cookie 但实为 sessionStorage）
- `wisnote/auth.py`：`login` / `get_user_by_token` / `purge_expired_sessions` / `revoke_all_sessions` / `logout`
- `wisnote/config.py`：`SESSION_TTL_HOURS`
