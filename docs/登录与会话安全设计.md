# 登录与会话安全设计（WisNote）

## 当前方案：会话 Cookie + 标签页绑定

登录令牌的存储与读取由单个自建组件（`ui/wisnote_cookie_component/index.html`）完成，融合两种浏览器存储，兼顾安全与体验：

| 存储 | 作用 |
|---|---|
| **会话 Cookie**（无 `expires`） | 令牌本体；服务端从 HTTP 请求头原生读取（`st.context.cookies`），刷新稳定、无闪屏；关闭浏览器即失效 |
| **sessionStorage 标签页 ID** | 登录时写入随机 ID；关闭标签页后 ID 丢失，再次打开比对失败 → 强制重新登录 |

## 行为

| 刷新页面 | 关标签页再开 | 关浏览器再开 | 地址栏 | 闪屏 |
|:---:|:---:|:---:|:---:|:---:|
| ✅ 保持 | ❌ 重登 | ❌ 重登 | ✅ 干净 | 无 |

## 多层防护

- **地址栏无令牌**：令牌只存于 Cookie / sessionStorage，绝不出现在 URL，防截图与历史泄露。
- **服务端有效期**：令牌 12 小时过期（`config.py` 的 `SESSION_TTL_HOURS = 12`）。
- **一键止损**：侧边栏「🔒 账号安全」可查看有效令牌、吊销全部令牌（异常时立即下线所有设备）。
- **退出即销毁**：点「退出登录」同时清除 Cookie、sessionStorage 与服务端会话。
- **不写磁盘**：无令牌文件，无本地长期钥匙。

## 数据流

```
登录成功 → persist_login(token)
  ├─ 组件写 会话 Cookie["wisnote_token"] = token（无 expires）
  ├─ 组件写 sessionStorage["wisnote_tab"] = 随机 ID
  └─ 清空地址栏参数

刷新（F5）→ 服务端读请求头 Cookie → 校验通过 → 保持登录（无闪屏）

已登录每次运行 → enforce_tab_binding()
  └─ 读 sessionStorage["wisnote_tab"] 为空（关过标签页）→ 清除凭据 → 回到登录页

退出 / 吊销 → 客户端 Cookie/Storage 清空 + 服务端 sessions 行删除
```

## 涉及模块

- `ui/app.py`：`persist_login` / `try_restore_session` / `enforce_tab_binding` / `clear_login`
- `ui/wisnote_cookie_component/index.html`：写/删 Cookie 与标签页 ID、回传标签页 ID
- `wisnote/auth.py`：`login` / `get_user_by_token` / `revoke_all_sessions` / `logout`
- `wisnote/config.py`：`SESSION_TTL_HOURS`
