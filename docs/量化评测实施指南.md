# 量化评测实施指南

> 测的对象："你的切块500 + 你的PDF解析 + 你的0.4阈值 + 你的课程笔记"这个组合的效果。
> 本指南给出完整方法论和本项目的对接点，代码由你自己实现。

## 流程总览

```
① 准备语料 → ② 标注 gold set → ③ 逐题检索记排名 → ④ 计算指标
                                    ↓
              ⑤ 负例与阈值 → ⑥ BM25 对照 → ⑦ 消融实验 → ⑧ 解读与出表
```

## ① 准备评测语料

- 用 5~10 份**真实课程笔记**（PDF/Word/PPT/文本混合最好）；
- 建一个**专用评测账号**，不要和日常数据混在一起：

```python
from wisnote import auth
from wisnote.ingest import ingest_document, list_documents, delete_document

uid = auth.register("eval_user", "eval123")          # 已存在则改用 auth.login
for d in list_documents(uid):                        # 每次重跑前先清空旧数据
    delete_document(uid, d["id"])                    # 保证实验可复现
for f in ["笔记1.pdf", "笔记2.docx", ...]:
    ingest_document(uid, f, course_name="评测语料")
```

## ② 标注 gold set

文件：`eval/goldset.csv`（用 UTF-8 with BOM 保存，Excel 打开不乱码）

```csv
type,question,keywords,doc,category
normal,死锁产生的必要条件是什么,互斥条件;环路等待;不剥夺条件,操作系统.txt,literal
normal,多个进程互相等待资源谁都动不了是什么现象,死锁;环路等待,操作系统.txt,paraphrase
negative,今晚吃什么美食推荐,,
```

| 列 | 说明 |
|----|------|
| type | normal=正例 / negative=负例 |
| question | 自然语言问题，按学生会怎么问来写 |
| keywords | 判定关键词，分号分隔；命中**任一**即算命中 |
| doc | 预期来源文档（备查，不参与判定） |
| category | literal=字面题（含原文术语）/ paraphrase=改写题（口语化同义表达） |

**标注规则：**
1. 关键词要选"只有正确答案块里才有"的词，太泛的词（如"操作系统""管理"）会导致误判命中；
2. 改写题的问题里**禁止出现**原文关键词，否则退化成字面题；
3. 规模：正例 30~50 题（字面:改写 ≈ 2:1），负例 5~10 题；
4. 题目覆盖所有语料文件，别只盯着一份笔记出题。

## ③ 逐题检索并记录排名

```python
from wisnote.search import search_notes

results = search_notes(uid, question, top_k=5)
# results[i]["text"] 是第 i 名的内容（1 起始）
# 命中判定：从第 1 名往下找，第一个"text 包含任一关键词"的名次就是命中排名
# 未进 Top-5 → 记 None（未命中）
```

## ④ 计算指标

- **Recall@K** = 排名 ≤ K 的题数 ÷ 总题数
  例：18 题中 17 题进 Top-3 → Recall@3 = 94.4%
- **MRR** = Σ(1/排名) ÷ 题数
  例：排名 [1, 2, 5] → (1/1 + 1/2 + 1/5) ÷ 3 ≈ 0.567

分**总体 / 字面题 / 改写题**三张表统计。

**通过线参考**（自己定并在论文里说明依据）：Recall@5 ≥ 90%、MRR ≥ 0.8、改写题明显优于对照方法。

## ⑤ 负例与阈值测定

1. 每个负例取 Top-3，记录**最高相似度**；
2. 阈值 0.4 不是拍脑袋：观察**正例的最低分**和**负例的最高分**之间的间隔，
   取间隔中间偏安全的位置。间隔太窄（如 0.38 vs 0.42）说明该阈值在当前语料上不可靠；
3. 阈值用途：上线后低于它的检索结果不送去给 Qwen 回答——这是防幻觉的第一道闸门。

## ⑥ BM25 对照（baseline）

原理：传统关键词检索，按词频打分，"死锁"两个字必须出现才能得分。
数据源直接用 SQLite 里已入库的块：

```sql
SELECT id, document_id, page, para_index, text FROM chunks WHERE user_id = ?
```

实现要点：
1. 中文分词用 `jieba`（`.venv\Scripts\pip install jieba`），英文统一小写；
2. Okapi BM25 公式（k1=1.5, b=0.75）：

```
score(q, d) = Σ idf(t) · f(t,d)·(k1+1) / ( f(t,d) + k1·(1 - b + b·|d|/avgdl) )
idf(t) = ln( 1 + (N - df + 0.5) / (df + 0.5) )
```
其中 f=词频，df=含该词的文档数，N=总块数，|d|=块长，avgdl=平均块长。

3. 对每个问题同样取 Top-5、同样判定命中排名，与语义检索对比。

**预期结论**：字面题两者接近；改写题语义检索显著占优——这就是论文的创新点验证。

## ⑦ 消融实验（切块大小）

- 对比 CHUNK_SIZE = 300 / 500 / 800（重叠固定 50）；
- **注意**：改了切块参数必须**重新切块 + 重新向量化**才有意义，
  只改 config 不重入库等于什么都没变；
- 建议用临时 ChromaDB 集合做实验，跑完删除，不污染正式数据；
- 每种大小跑同一份 gold set，对比 Recall@K 和 MRR，选出最优值并说明理由。

## ⑧ 结果解读规则（诚实分析）

1. 语料太小时 Top-5 ≈ 大半个库，所有方法都接近满分，区分度被压缩；
2. 样本小时 1 题的波动就是几十个百分点，差异可能在噪声内——**必须给出题数**；
3. 中文分词后改写题与原文常共享字符，BM25 不会完全失效，这是正常现象；
4. 对每个"未命中"的题做人工归因：切块切断了答案？关键词标错？还是语料里根本没有？
   归因分析是论文加分项；
5. 结论只声明数据支持的范围内的事。
